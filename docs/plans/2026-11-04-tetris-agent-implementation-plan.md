# Tetris Agent 实施计划

日期：2026-11-04
状态：本轮实施完成；第 12 节场景已按真实运行与受控故障验证覆盖，证据及验证边界见 [实施进度](./2026-11-04-tetris-agent-progress.md)。未运行不必要的全量测试；发布安装包和人工点击系统横幅不在本轮已验证范围内。
前置资料：[Super Agent 研究与计划](./2026-11-03-tetris-super-agent-research-and-plan.md)

## 1. 目标与范围

将现有 Super Agent 升级为 App 级的 **Tetris Agent**：使用独立 Claude Code runtime、独立会话与长期记忆，自动感知 App 中的工作目录及 tiles，根据需要创建 Task，将执行工作交给 Claude Code 或 Codex worker。在任务运行、等待人工决策和回报期间，用户仍然可以继续主对话。

Tetris Agent 拥有自己的独立画布页面。IDE 画布继续用于用户日常编辑和组织工作；Agent 自动创建的 worker、报告、任务关系与回放在 Agent 画布展示，不挤占 IDE 布局。

本轮实施覆盖：

- 名称与图标统一为 Tetris Agent 和现有 Tetris logo。
- Agent Home、原生会话恢复、长期记忆、新对话与历史对话。
- 自动工作空间上下文、默认 Worker 配置与任务目录解析。
- Task 持久化、执行、自然语言决策、回报和双层通知。
- IDE / Agent 独立画布与隔离的任务回放。
- 数据迁移、异常恢复与端到端验收。

“在 App 内人工接管 worker 的完整聊天界面”可作为后续增量；“在原生终端接管同一 Claude session”需单独验证，不作为本轮承诺。Task 中的自然语言决策和继续执行属于本轮范围。

## 2. 已确认的产品原则

1. 用户与 Tetris Agent 聊需求，不必先指定一个工作目录。
2. 主管运行在自己的 Agent Home；worker 才运行在具体项目目录或独立 worktree。
3. 工作空间信息由 App 注入。目标明确时自动选择，真正歧义时才询问。
4. 默认 worker 可选 Claude Code / Codex；用户明确指定优先，已有 Task 默认沿用原执行器。
5. 派发工具确认 Task 持久化并入队后立即返回，不等待 worker 完成。
6. 决策卡呈现问题、背景和建议，不做表单；用户用自然语言表达决定。
7. 只暂停需要决策的 Task，不阻塞主对话和其他任务。
8. 新建或切换主对话不取消旧 Task；回报归属原对话，不串入当前无关对话。
9. Task 保存真实事件、用户决定、执行轮次和产物版本。回放重现记录，不重新执行。
10. IDE 画布、Agent 实时画布、回放展示状态相互隔离。
11. 任务完成不等于用户验收；报告存在不等于执行成功。
12. 原有流光连接、完整边框、选中强调、内部滚动和自动留白能力继续保留。

## 4. 页面与画布设计

### 4.1 两个独立工作页面

**IDE 页面**：保留用户的文件、编辑器、终端和自由画布。Agent 可读取其工作空间与所选 tiles 的上下文，但自动派工不改变 IDE 布局。

**Tetris Agent 页面**：建议采用左侧对话历史 / Task 列表、中间 Agent 画布、右侧主管对话的组织方式；面板可收起。具体宽度沿用 App 现有设计规范。

这是与 IDE 并列的工作页面，不依赖把 IDE 画布腾空来展示 Agent。标题栏使用一个「Tetris logo + 当前画布」下拉入口，菜单中选择 IDE 画布 / Tetris Agent，并显示任务未读数。项目筛选属于 Agent 画布上下文，适应全部任务与缩放读数留在画布角落，不再将这些操作并排堆在顶部。返回 IDE 时收起 Agent 对话面板；再次进入 Agent 页面恢复其对话、画布布局及任务焦点。

Agent 画布承载：

- 自动派发的 worker tiles。
- 关联报告及产物 tiles。
- 任务分组、状态、委派 / 回报流光与常驻关系线。
- 当前 Task 的决策提示及执行节点。

点击对话中的 Task card，定位 Agent 画布中的对应任务；用户从 IDE 打开通知时，进入 Agent 页面并定位，不把 worker 搬进 IDE。

两页共享 App 已注册项目和文件引用，分别拥有自己的 tiles 与展示状态。后台任务可以读取派发时注入的 IDE 上下文，但不能因创建 Worker、展开报告或收到回报而抢走 IDE 的页面、选中项和视口。

### 4.2 画布作用域与状态

建议模型：

- `ide:<workspaceId>`：用户工作画布，沿用现有布局数据。
- `agent:live`：Agent 的持久化实时画布，以 Task 分组，可按对话或项目筛选。
- `agent:replay:<replayId>`：临时回放状态，不写回实时布局。

每个作用域独立保存 viewport、tiles、groups、selection、focus 和关系线。画布 RPC、tile lookup、保存恢复、连线定位、焦点管理均需显式携带或绑定 `canvasId`，不能仅做页面隐藏。

实时 Agent 画布与 Task 生命周期独立于页面是否可见。隐藏页面也能接收任务更新；切回页面时从状态恢复，不重新派工。新建主对话不清空实时画布，可通过筛选聚焦当前对话。

### 4.3 回放视图

在 Agent 页面进入回放模式，直接在独立只读画布重现委派、Worker 创建与执行、决策及报告打开；不再另画流程节点卡或常驻事件列表。底部保留精简播放栏和“返回实时任务”入口。运行中的任务继续在后台更新，回放停留在所选历史事件；退出后恢复实时画布的 viewport、选中项和布局。

回放使用任务记录生成展示节点，不启动真实 worker，不创建可执行终端，不调用实际派发 / 决策 / 通知接口。报告展示对应历史版本，避免读取后来覆盖的结果。

### 4.4 视觉与交互

- 任务卡与 worker 的连接起点绑定真实卡片，不绑定整段回复或侧栏。
- 自动布局默认保留约 100 个画布单位的间距；缩放后若过密，允许聚焦任务以展示连线。
- worker 获得焦点后保持 `canvas-tile` 所有权，普通滚轮滚动内部内容。
- 画布空白处滚动控制画布；缩放和既有 Shift / Space 手势保持明确分工。
- 流光表现派发和回报方向；完成后保留细关系线。
- 页面不可见时不持续播放动画；恢复时显示当前状态，不补播所有历史闪动。
- 支持 reduced-motion；回放保留阶段信息但减少运动。

## 5. Agent Home、会话与记忆

建议目录：

```text
<app-user-data>/tetris-agent/
  CLAUDE.md                   身份、职责、交互与工具边界
  MEMORY.md                   跨对话的重要偏好和已确认约定
  memory/workspaces/          按 workspaceId 保存项目记忆
  conversations/              对话记录、摘要、Claude session 映射
  tasks/                      Task、执行轮次、决策与事件
  artifacts/                  版本化报告及产物索引
```

不写入安装包；开发和正式环境沿用现有隔离规则。使用该目录作为主管 runtime cwd，不随用户当前项目切换。

### 5.1 Claude runtime

- 每个 conversationId 对应独立 Claude session；多轮复用，历史对话支持恢复。
- App 维护对话账本、工具调用记录和 session 映射；不能把 Claude transcript 当作唯一状态来源。
- 复用现有 ACP / Claude 接入能力，提供受控的 App 工具接口，不继续以“每轮无会话 JSON 决策”作为最终架构。
- 工具包括工作空间查询、Task 创建 / 查询 / 补充 / 取消、决策提交、记忆读取与更新。
- 主管负责调度和沟通；项目文件修改、构建、测试等执行工作由 worker 承担。职责边界由工具能力约束，不能只写提示词。
- 明确加载 CLAUDE.md 和记忆的路径与流程，不假定仅创建 MEMORY.md 就会被自动使用。
- 启动失败、恢复失败需明确展示；不得悄悄开启新 session 并声称完整延续旧会话。

### 5.2 记忆策略

- 对话历史：原始消息和工具结果，按 conversationId 保存。
- 长期记忆：用户偏好、长期约定、确认后的项目事实，记录来源与更新时间。
- Task 事实：从任务账本读取，不依赖模型记忆。
- 多会话共享记忆写入经 App 串行、原子提交，避免互相覆盖。
- worker 输出属于待核实材料，不自动升级为用户偏好或已确认事实。
- 支持查看和编辑记忆；初始化模板升级不能覆盖用户修改。

## 6. 自动上下文与 Worker 配置

每轮由 App 提供带版本和时间的上下文快照：已添加的工作目录、项目名称、当前 IDE 工作空间、用户选中的 tiles / 文件、Agent 当前 Task 焦点、运行任务、待决策事项与未读回报。

只注入需要的元数据；大文件和长日志按需读取。区别“当前查看的目录”“用户选中的内容”“本 Task 的执行目录”，避免切换页面导致任务目录漂移。

派发时生成明确 TaskSpec：目标、workspaceId、执行 cwd、执行器、范围限制、预期产物与必要验收条件。目录解析不明确时询问；明确后固定到 Task，执行前检查目录可用性。

默认 Worker 选择规则：

1. 用户本次明确指定。
2. 已有 Task 沿用原执行器和 session。
3. 新 Task 使用设置中的默认 Worker：Claude Code / Codex。

默认配置变更仅影响新 Task。执行器不可用时说明原因，不静默切换。独立 worktree 继续作为可选执行模式，并记录 sourceCwd 与 executionCwd。

## 7. 持久化模型与一致性

建议逻辑实体如下；存储实现需支持事务或等价的原子提交与恢复机制：

| 实体 | 关键字段 |
| --- | --- |
| Conversation | id、title、runtimeSessionId、createdAt、archivedAt、消息与摘要 |
| Task | id、originConversationId、originMessageId、workspaceId、sourceCwd、executionCwd、provider、状态、验收状态 |
| TaskRun | id、taskId、workerSessionId / threadId、指令、开始结束时间、状态、前序轮次 |
| DecisionRequest | id、taskId、runId、问题、原因、建议、影响、状态 |
| DecisionResponse | id、requestId、用户消息 ID、用户原话、Agent 解释、交付指令、提交状态 |
| TaskEvent | id、taskId、runId、单调 sequence、时间、actor、类型、关联消息 / 决策 / 产物 |
| Artifact | id、taskId、runId、version、类型、路径、内容摘要 / hash |
| Notification | id、eventId、taskId、conversationId、未读状态、系统投递状态 |
| CanvasState | canvasId、viewport、tiles、groups、links、选中与焦点 |

关键约束：

- Task、主管对话和 worker session 是不同身份，不共享主键。
- 新建、排队、派发使用幂等 operationId；重复工具调用不能创建两个 worker。
- 决策请求只接受一次有效提交；陈旧请求不能推动新的执行轮次。
- 每条回报先持久化，再更新投影与发通知；总结失败不能丢失原始结果。
- 回报按 runId 校验，迟到的旧轮次结果不得覆盖新状态。
- 同一 worker session 同一时刻只有一轮写入 / 执行；补充指令有明确队列。
- 派发意图、外部执行和确认之间保留恢复状态，不能在崩溃后盲目重试执行。

## 8. Task 生命周期、报告与自然语言决策

建议 Task 展示状态：准备中、排队中、执行中、等待决策、等待授权、受阻、待验收、已验收、失败、已取消、已中断。事件中保留原始 worker stop reason，不能把所有正常返回都视为成功。

### 8.1 派发

用户需求 → 主管解析 → App 保存 Task 和派发意图 → 对话出现 Task card → Agent 画布创建 worker → worker 接收并执行 → 主对话继续。

Task card 可展示已入队状态，但只有收到执行确认后才展示“执行中”。worker 创建失败保留 Task 和错误，不伪造运行节点。

### 8.2 回报协议

统一适配 Claude / Codex 的语义回报：completed、blocked、needs_decision、needs_permission、failed。包含 taskId、runId、摘要、必要证据、产物、未完成事项及决策内容。

优先使用受控 worker 回报工具；执行器不支持时使用经过校验的结构化输出适配。不得仅凭某句自然语言含有“需要确认”就直接改变执行状态。现有授权回调直接进入权限事件通道。

App 将异常退出、断连、超时和工具错误映射为技术故障事件；worker 未能主动回报时仍有可靠状态记录。

### 8.3 自然语言决策

决策卡呈现“需要决定什么、为什么、建议及影响”。不强制表单或选项按钮，用户仍在主输入框自然语言回复。

- 点击决策卡只选择 Task，在输入框旁显示关联上下文。
- 唯一且明确的待决策问题可自动关联；多个候选或歧义时简短澄清。
- 不完整回复继续追问；讨论、提问、沉默不视为同意执行。
- 同时保存用户原话、主管解释及实际发送给 worker 的指令。
- App 校验请求仍有效、目标 session 正确、当前阶段可继续，然后恢复执行。
- 更新卡片为“已决定：……”，继续写入执行事件。
- 需要授权的操作保持具体范围；自然语言决定通过原权限通道落实，不转换成长期无限授权。

优先恢复原 worker session。无法恢复时，保持 Task 不变，创建新 run，带入目标、产物、已完成工作、阻碍和用户决定，明确说明恢复方式。

### 8.4 报告

区分三类内容：执行日志、最终结果摘要、正式产物。约定 worker 最终结果包含完成内容、变更 / 产物、验证结果、未完成事项。

每个 run 独立保存结果；报告按版本不可变归档。取消或失败的部分输出明确标记状态，不包装为成功报告。Task 当前视图可展示最新版本，历史回放必须读取当时版本。

## 9. 新对话、异步回报与通知

新对话创建新的主管 session，不清空长期记忆、不停止旧 Task。归档对话与取消任务是独立操作。

回报始终写入 originConversationId，并更新全局 Task 列表：

- 用户在原对话：展示回报事件和总结，保持输入框可用，不强制滚动打断阅读。
- 用户在其他对话：增加原对话未读和通知，不插入无关聊天。
- 原对话已归档：结果仍在 Task 中可见，通过通知进入任务详情。
- App 重启：恢复未读和待总结事件，先核对 session / worker 状态，不自动重跑任务。

通知顺序：保存结果 / 决策请求 → 更新 Task 与未读 → 发布应用内和系统通知 → 主管异步总结。

应用内：Tetris logo 未读标记、Task 状态、通知列表。系统层：App 不在前台或相关任务不在查看范围时按用户配置提示；系统不允许通知时，应用内记录仍可用。

查看范围以当前页面实际可见的 Task card / Worker 为准。停留在 IDE、查看其他任务或播放历史回放，均不能当作已经看见实时回报。隐藏的 Agent webview 不能自动清除原对话未读。原生通知投递先记录尝试状态；崩溃后恢复尚未尝试的通知，对结果不明的系统投递不重复弹窗，应用内未读始终保留。

通知覆盖完成、失败、受阻、需要决策和授权，按 eventId 去重。点击系统通知唤起 App，打开 Agent 页面和对应原对话 / Task。回放不发通知。

主管的单个 session 仍需串行执行模型 turn；允许继续输入和排队不等于同一 session 并发写入。用户消息优先处理，回报先即时显示状态，多个结果可合并总结，避免长时间阻塞主对话。

## 10. 真实事件记录与画布回放

需要保存的事件至少包括：

- 任务创建、目录和执行器确定、入队、派发确认。
- worker 创建 / 关联、开始执行、关键工具活动、进度。
- 阻碍、失败、重试、决策请求、用户回复、决定交付、恢复执行。
- 产物生成、报告版本、完成回报、主管总结、人工验收。
- 报告在 Agent 画布打开、任务关系节点关联等展示事件。

工具原始大输出作为独立日志引用，时间线保留摘要和索引；不能沿用仅保留最近 100 个工具项的内存数组作为完整执行历史。

回放引擎读取固定事件快照，按 sequence 推进画布投影：委派气泡 → worker tile 出现 → 在同一 tile 更新工具 / 进展、决策问题与用户原话 → 继续执行 → 打开历史报告 tile → 回报。使用流光表现委派及回报，保留对象之间的关系线。只有真实报告打开事件才出现报告 tile；仅归档时在 Worker 中呈现保存结果。时间顺序与真实记录一致，长时间等待默认压缩且标明。

控制项：播放 / 暂停、进度条按事件跳转、速度、压缩等待、返回实时。不需要独立节点列表，完整事件及用户原话仍保存在记录中。运行中 Task 回放到当前快照末尾即停止，不把新事件混进历史游标。

回放是只读投影：不派发、不恢复 session、不写决策、不发通知、不改变真实任务状态和实时 tile 布局。缺失产物展示“历史文件不可用”，不能改用最新文件冒充。

## 11. 分阶段实施

### P0：冻结数据契约和迁移方案

- 明确 Conversation / Task / Run / Decision / Event / Canvas 身份与字段。
- 明确回报协议、幂等策略、通知顺序和状态转换。
- 备份现有对话、任务、画布；添加 schemaVersion 和迁移测试样本。

验收：同一工作目录可关联两个独立对话；Task 归属可准确表达；旧数据可读取并保留。

### P1：独立 Agent 页面、画布作用域与品牌

- 统一 Tetris Agent 文案和 logo。
- 实现 IDE / Agent 页面与独立 CanvasState。
- RPC、持久化、tiles、focus、关系线按 canvasId 隔离。
- 新任务仅创建到 Agent 画布，隐藏页面也能同步状态。
- 保留 100 单位留白、流光、内部滚动与 reduced-motion。

验收：派发 / 打开报告 / 切换页面不改变 IDE 的 tiles 和 viewport；worker 内滚动不移动画布。

### P2：Agent Home、Claude session 与默认 Worker

- 初始化身份模板和记忆目录；接入可恢复的主管 Claude session。
- 实现新对话、历史切换、归档和 session 恢复失败提示。
- 自动注入 App 上下文，删除“必须先选工作目录”的主对话前提。
- 增加默认 Worker 设置和派发目录解析。
- 记忆读写通过 App 管理，带来源及串行更新。

验收：用户不选目录即可提需求；有歧义才澄清；新对话独立上下文，旧对话能恢复；默认执行器只影响新 Task。

### P3：Task 事件账本、派发与结果协议

- 拆分 Task 身份和 worker session，建立 originConversationId。
- 持久化派发意图、run、关键事件、结果及不可变产物。
- 适配 Claude / Codex 回报，覆盖正常完成、故障和部分输出。
- Task 列表按当前对话、项目、全部范围筛选。

验收：派发后主对话可继续；一次调用只创建一个 Task / worker；重复回报和迟到结果不污染状态；报告版本可追溯。

### P4：自然语言决策、异步总结与通知

- 实现无表单决策卡、输入框 Task 上下文、自然语言关联与澄清。
- 校验和持久化决定，恢复原 worker 或明确创建恢复 run。
- 回报先落库通知，主管再异步总结；用户消息优先。
- 接入应用内和系统通知、未读、点击定位与去重。

验收：两个 Task 同时待决策不会串单；决定只交付一次；旧对话回报不串入新聊天；主管暂时不可用仍能收到通知并查看结果。

### P5：事件驱动回放

- 将固定阶段演示替换为事件投影。
- 建立隔离回放画布，展示决策和历史报告。
- 支持暂停、跳转、速度、等待压缩与退出恢复。

验收：回放完整呈现“受阻 → 人的原话 → 继续执行 → 结果”；重复回放不产生新任务、重复通知或真实命令；实时工作不受影响。

### P6：迁移、恢复和整体体验验收

- 执行旧数据迁移；原来按 cwd 的聊天各迁成一条历史对话。
- 旧 Task 有明确关联时绑定原对话，否则进入历史任务列表，不猜测来源。
- 旧 worker / 报告仅在可识别关联时迁入 Agent 画布；不移动用户无关 tiles，保留迁移备份。
- 旧数据缺少事件时展示“历史记录不完整”，可保留明确标注的示意回放，不伪造执行细节。
- 验证崩溃重启、后台通知、目录删除、worker 失联和历史产物缺失。

验收：迁移可重复执行且不重复创建数据；重启不重复执行任务；历史聊天、报告与用户 IDE 布局保留。

## 12. 必须完成的端到端验收场景

1. 添加两个项目，在未选择目录的主对话中明确指定项目名称，正确派发到目标目录。
2. 含糊地说“修改这个项目”且没有明确上下文时，主管澄清，不随机选择目录。
3. 默认 Worker 为 Codex，显式要求 Claude 时使用 Claude；继续旧 Task 不受默认值变更影响。
4. Task 执行时继续聊天、再创建 Task、切换和新建对话，原任务保持运行。
5. worker 需要决策，展示卡片并通知；自然语言决定继续同一 Task，保存用户原话及实际指令。
6. 两个待决策 Task、重复回复、陈旧回复，均不误派或重复恢复。
7. 主管总结失败，Task 原始结果、报告和未读通知仍可用。
8. 旧对话任务完成，系统通知定位原对话及 Task，不污染新对话。
9. IDE 与 Agent 画布切换、重启恢复、后台派工，布局与焦点互不串扰。
10. 真正 Electron webview 中单击 / 双击激活 worker 后，内部内容滚动，画布不动。
11. 回放含决策的多轮任务，历史报告版本正确；暂停与跳转不影响真实 worker。
12. 回放期间真实任务有新进展，退出后展示最新实时状态，同时恢复实时布局。
13. 崩溃发生在派发、决策交付或通知投递边界，恢复后无重复执行、无重复决定、无丢失结果。
14. 删除目录、session 恢复失败、取消任务、清理 tile，不丢失 Task 历史和产物索引。

## 13. 本计划的交付标准

用户无需管理主管的工作目录，就能持续与 Tetris Agent 对话。Agent 根据 App 上下文创建 Task，在独立 Agent 画布派发 worker；需要人判断时通过决策卡说明问题，接收自然语言决定后继续。任务记录、会话归属、结果与通知可靠保存，任一 Task 都可按真实事件回看；IDE 日常画布始终保持独立。
