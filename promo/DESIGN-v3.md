# Tetris V3：把工作过程放进画布

28 秒，1920×1080，30 fps。延续 V2 的多个终端、文件预览、浏览器画布、分组和完成提醒。参考 Silieco V3 的分镜、场景源码，以及 product-promo-video 的叙事、视觉、动效和无头导出规范。未复用 Silieco 的人物、品牌或业务能力。

## 镜头与动作

| 时间 | 主要动作 | 动效和声音 |
| --- | --- | --- |
| 0–2 秒 | 开场：终端成为工作空间 | 三张动态终端错峰入场，轻微旋转归位 |
| 2–6 秒 | 多个终端，各自推进 | Anime.js stagger；独立命令输入、逐行日志、测试状态和不同相位光标 |
| 6–10 秒 | 文件在画布中预览 | 镜头平移、预览卡描边、卡片间曲线路径与轻提示音 |
| 10–14 秒 | 浏览器与工作内容并排 | 连续镜头、浏览器边框聚焦、对应章节标签 |
| 14–18 秒 | 相关终端组织成组 | 分组边框绘制、收起和展开；示例日志继续推进 |
| 18–22 秒 | 完成提醒返回测试结果 | 测试逐项完成、通知滑入、点击光环、终端放大 |
| 22–25 秒 | 同一画布的完整上下文 | 镜头拉远、关系线展开、保留窗口与内容的位置 |
| 25–28 秒 | 品牌收尾 | 三项能力依次出现，和弦与提示音收束 |

边框使用浅灰绿细线、内侧高光、15px 圆角与轻阴影。选中反馈用局部描边，避免整屏闪光。所有内容与连线共享世界坐标，旁注明确宽度，日志在独立视口中滚动。

## Anime.js 接入

锁定 Anime.js 4.5.0。`anime-motion.mjs` 创建 `autoplay:false` 的对象时间线，由当前帧对应的毫秒数调用 `seek(time,true)`；React 只读取当帧结果。没有自动播放、CSS keyframes、计时器或网络状态驱动动画。

- [中文动效参考入口](https://animejs.cn/)
- [官方 Timeline](https://animejs.com/documentation/timeline/)
- [绝对时间 seek](https://animejs.com/documentation/timeline/timeline-methods/seek/)
- [stagger](https://animejs.com/documentation/utilities/stagger/)

`node scripts/check-motion.mjs` 对 840 个帧号按顺序、倒序和乱序采样，验证结果一致。终端内容同样直接由帧时间决定；它是演示脚本，没有执行真实命令。

## 素材与导出

现有 Tetris 图标、生产组件截图、Markdown/图片/浏览器预览足够完成本版，不需要新素材。窗口内部的动态日志为重建演绎；角落标明演示输出。曲线是宣传片的视觉说明，不表示产品自动在窗口间传递数据。

中文字体使用本地 Noto Sans SC 子集并等待加载，OFL 授权随字体保存。等宽字体使用系统字体栈，跨系统字形可能不同。音乐与提示音为原创合成，分轨和混音都保留，无人声旁白。

沿用已验证的 Chrome Headless Shell 149 + ANGLE + PNG + 单并发 + 禁用 GPU 栅格化。先检查关键帧和动态短片，再导出全片，执行帧数、空白帧/孤立闪帧、完整音视频解码与音频峰值检查。启发式检测不能保证所有播放器和平台都绝对无频闪。
